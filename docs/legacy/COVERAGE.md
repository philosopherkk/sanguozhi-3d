# 兩國各時代事件覆蓋總覽（COVERAGE）

**這支檔案回答一個問題**：「中國與日本、所有時代的歷史事件，都覆蓋好了嗎？」
其他 HANDOVER 章節記的是單次工事的經過；這裡記的是**還差多少**。

覆蓋有兩個維度，**兩個都要达标才算「覆蓋好」**：

- **廣度**：這個時代有沒有足夠的事件條目（沒有條目，深度再好也輪不到顯示）
- **深度**：每條事件的三段（起因／經過／結果）是否達大學生程度
  （起因 ≥200 字、經過 ≥200 字、結果 ≥400 字，由 `audit:event-depth*` 量）

## 三、口徑與限制（讀這張表時要記住）

1. **事件數 ≠ 該時代的全部事件。** 525 條是「已登錄的條目數」，不是「應該有的條目數」。
   廣度是否足夠要逐時代判斷，不能只看數字。
2. **深度門檻是字數代理，不是品質判準。** 200/200/400 只能抓「寫得太短」，
   抓不到「寫得長但空洞」。加厚要靠結構性原因＋轉折＋史料保留
   （寫法見 `docs/TONIGHT.md` 任務 1），**為過閘門灌水是最壞的用法**。
3. **引用欄不算錯。** `source`／`outcomeSource`／`classicQuote` 保留原典字形與
   原始書名；只有我們寫的中文要繁體。
4. **`audit:quotes` 那 14 條是下限**，不是缺口（原典在維基文庫沒有全文，
   見 HANDOVER 1AG/1AH）。

## 四、要跑到「都覆蓋好」需要什麼

- **深度**：**已達標**（R4 輪，三個閘門皆 0）。525 條的起因全部 ≥200 字，
  經過全部 ≥200 字。實測速度每輪 25–45 條——寫得合格的起因要查材料、要標史料層別，
  速度就是慢，這是它的真實成本。
- **廣度**：七個時代要先做一次「這個時代該有哪些事件」的清單，
  再決定補哪些條目。這一步**需要人工判斷**，不能自動生成——
  自動生成事件清單正是編造史實的典型路徑。
- **現在只剩廣度這一維度未決**，而且它由使用者定調，不由閘門決定。
