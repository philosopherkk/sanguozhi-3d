# 事實查證升級協定（什麼時候停、怎麼提問）

目的：當我（或任何一輪 agent）**快要編造**的時候，及早把問題交給你，
由你轉給前沿模型或自己去查。提問要寫成**可被回答的形狀**，
不是把我自己的猜測包裝成問題。

今天這一輪提供了四個真實案例，都在下面標為「反例」——
**其中兩個的錯不在答案，而在我提問的方式。**

---

## 一、信號：看到這些就停下來問，不要寫

### S1 我在用「形状」推測，不是用「讀過」推測
- 我看到書名結尾是「實錄」就推定它是佚書／或推定它可用。
- 我看到書名結尾是「傳」就假定它屬於同一部書。
- **反例（今天）**：我懷疑《則天實錄》被用来支撑細節，實際那條早就寫了
  「不存，其事見《舊唐書》《資治通鑑》」。**我是從書名形状推出缺陷的，
  沒有讀那一條。**報假警比不報更糟。

### S2 兩個專名之間的關係「聽起來合理」
- 「A 與 B 簽條約」「C 是 D 的作者」「E 書載於 F 庫」——凡是我覺得
  順理成章的**關係**，都要查。字我認識不等於關係我核過。
- **反例（今天，最貴的一條）**：原文寫「1921 與**美國**單獨簽《中德協約》」。
  這句話在語感上完全通順，所以我在旁邊寫註解、改字形、跑閘門，
  一路都沒有碰到它。錯的是**對象國**。

### S3 我把不確定的幾個東西捆成一個問題
- **反例（今天）**：我一次問了「言經卿記 黃慎 燕行錄」。
  這三者毫無關係（日本公卿日記／揚州八怪的畫家／朝鮮使華錄）。
  **捆綁本身就暴露我在做模式匹配而不是知道。**
  一個問題一個實體一個關係。捆綁的問法會讓回答者替我補連結，
  於是錯的連結被當成前提接受。

### S4 同一類缺陷我已經找到第 N 次
- 今天是**第 9 次**發現「閘門清單缺字」（`宝`、`贾`、`晋`、`画`、`戦`、`図`…——**此處是在指稱那些字本身**）。
- 同一類錯誤重複出現 → 問題在**偵測器**，不在內容。
  此時要問的是「這條規則該怎麼定」，不是「這個字怎麼改」。

### S5 我準備寫出具體卷、頁、日期、人名、引文
- 任何**卷號／頁碼／簽約日／作者歸屬／逐字引文**，若不是從同一檔已有內容
  复制或推得，就要查。閘門 `audit:fact` 會把無法佐證的數字擋下來——
  它今天擋掉我加的「31」（北京專條簽訂日），那是**對的**，
  因為它確實來自外部查證，所以要記 allowlist 而不是把門檻抬高。

### S6 我在「補全」一個看起來殘缺的東西
- **反例（今天的正例）**：《兼卿記》我判斷是《言経卿記》的殘缺標題——
  這個判斷成立，但它成立的唯一理由是**同一模組別處已經出現全稱**。
  沒有可參照全稱時就跳過並記錄，不要補。

### S7 我需要的是「判斷」而不是「檢索」
- 凡答案取決於**史學界共識、真偽爭議、輯本可靠性**，
  我不該自己裁定。例：某篇《尚書》是今文還是古文定型。

## 二、提問格式（給前沿模型用）

一個問題一個區塊。不要把多個實體混在一塊。
每一塊必含五個欄位，缺任何一個都會得到不可用的答案。

```
【_entity】      要查的單一對象，逐字給出（含書名號、異體字原樣）
【where_used】   它在我們資料裡的什麼位置：檔案:行、事件 id、年份、欄位
【claim】        我們用它支撐了哪一句話（逐字貼出，不摘要）
【question】     一個封闭式問題（能用 是/否/未知 + 依據 回答）
【answer_form】  要求回答者照這個結構回，且不許編卷頁
```

`【answer_form】` 固定要這幾項，這是讓答案可直接落回資料的關鍵：

1. **verdict**：supported / unsupported / unknown（unknown 必須允許，
   而且要寫出「不知道什麼」）
2. **standard_title**：正式書名／條約名（繁體），以及**常見異體與日文原形**
   ——我們的閘門對字形敏感，不知道變體就會改壞引文
3. **survives?**：原書存／佚／僅見於他書轉引／僅輯本；若輯本，是哪一家輯本
4. **layer**：這個記載屬於實錄層／軍記層／類書轉引／注引／後世合成
5. **primary_source**：可核的一手出處（書名＋卷或篇，**不許編卷頁**）
6. **search_terms**：3–6 個可自己驗證的檢索字串（給人去查，不靠模型自證）
7. **confidence**：high / medium / low ＋ 理由

### 三個必加的防呆句

- 「若不知道，回答 unknown，並說明哪一部分無法確認。**不要用看似合理的書名填補。**」
- 「不要提供卷號與頁碼，除非你能指出可核的來源；無法指出就寫 `卷頁：未核`。」
- 「若我的提問本身含有錯誤前提（把兩個無關對象並列、或預設了不成立的關係），
  **先指出前提錯誤**，再回答。」
  ← 這一句今天救了一輪：言経卿記 那條就是回答者指出我的前提錯了。

## 三、批次提問（量大時）

多於 10 條時用表，每行仍是一實體一關係，但**只查存在性與字形**，不查深層論點：

```
對每一行給：exists? / standard_title / 常見異體 / survives? / 一句話依據
不要對批次裡的每一條做深層論證——深度問題要單獨提出。
```

深度問題（論點歸屬、真偽爭議、輯本可靠性）**一律單提**，
並附我們那一句 claim 的逐字原文。

---

## 四、答案怎麼落回 repo（不要只讀一遍）

1. `supported` → 不動；必要時補第二處對讀來源。
2. `unsupported` 且知道正確來源 → 換掉出處。
3. `unsupported` 且不知來源 → **把主張降格為明示的不確定**（「本條未載」「一說」「佚書，今僅見於…」），
   或刪掉那句。
4. 外部查證得來的日期／卷次 → 記 `reports/fact-allowlist.json`（模組 id → 數字 → 依據），
   **不要抬高閘門門檻**。
5. 異體字／原題字形相關的結論 → 記 `reports/chars-allowlist.json`，
   寫明「哪個檔、哪個字、憑什麼」。
6. 每一輪把結論寫進 `docs/RESEARCH-ASKS.md` 的「已結案」表，
   讓下一輪不必重問。

## 五、機械化

`npm run audit:citations -- --ask` 會把分診表裡**我判不了**的條目
（層 C／層 E）直接印成上述格式的提問區塊，按問題類型分組：

- `A 存在性與字形`：這本書是否存在、正式名、異體、是否存世
- `B 論點歸屬`：這位學者是否真的這樣主張
- `C 引用層別`：原書／輯本／注引／類書轉引，該標哪一層
- `D 條約與法令`：正式名稱、日期、當事方
- `E 歧義歸屬`：這個簡稱指哪一部書

生成物只是**提問**，不是結論。結論要人與前沿模型回答後寫回。
