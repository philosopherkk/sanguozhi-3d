## 單一項目的做法（照這七步）

1. 在列表取一列，例如 `結果｜20｜src/zhou/data/earlyDynasty.ts｜zhou-zhao｜703`。
2. 讀該事件整個物件（約 30–40 行）：`read` 該檔從行號往上 8 行起、往下 35 行。
3. 找出事件裡**已有的依據**：`source`、`classicQuote`、`classicSource`、`note`、另兩段（起因／經過／結果中已寫的那兩段）、`keyFigures`。
4. 只用這些依據與可驗證的史料來寫。要引用原文時，先用 `python3 scripts/qsrc.py '<書名/卷N>' '<正則>'` 逐字核對，看輸出裡「匹配 N 處」那一行；N 為 0 就不能當逐字引文。日本史料用 `--host ja.wikisource.org`。
5. 寫出新文字，用 `edit` 替換該欄位。保持該檔原本的欄位格式（單行字串就寫單行字串，不要自己換成模板字串或加 `+`）。
6. 數字數：`python3 -c "print(len('<剛寫的文字>'))"`。未達門檻就補，補的內容仍要有依據。
7. 單項驗證：`node scripts/audit_event_depth.mjs`，確認該列從表中消失、且「灌水嫌疑」沒有增加。

## 怎麼寫才算「加厚」（重點）

**做**

- 寫具體的人、年、地、書：誰在哪一年做了什麼，哪部書怎麼記。
- **史料本身的限制也是內容**。早期史（夏、商、西周）常常沒有第一手記載，這時就老實寫：哪些書提到、說法有哪些分歧、考古與文獻能互證到哪裡、哪些部分只是後人推算。這是本站的寫法，例如：「本紀對此事記載極短，不寫起因與交戰；古本《竹書紀年》輯本另有條目，但屬後人輯佚。」
- 有爭議的年份或數字，設 `disputed: true`，並在 `note` 寫明各說與出處。
- 結果欄要回答三件事：直接後果、對後來局勢的影響、地圖上色塊或路線有沒有因此變動（沒有變動也要說明為什麼不變）。

**不做**

- 不寫空話：「這件事影響深遠」「具有重要意義」「對後世產生了重大影響」。
- 不把同一句話或同一個樣板套到多個事件（會被偵測為灌水，等於惡化）。
- 不為了湊字數重述同欄位前面已寫的內容。
- 不從記憶補細節。「記得好像是」＝不確定＝不寫。
- 不改 `id`、`year`、`source`、`disputed` 的既有值，除非你已用原典證明它是錯的（那是 accuracy 的工作，這裡只在報告提出）。

**對照例**（只示範性質，不要照抄內容）

- 差：「周昭王南征後，周朝受到很大影響，局勢發生了變化，影響非常深遠。」（空話，沒有人名、書名、年份）
- 好：「《周本紀》只記昭王南巡不返、卒於江上，並明言訃告不發。其後立昭王子滿，是為穆王。絕對年份出自後世長曆推算，不是當時的紀年。」（有書名、有人物、有限制）
